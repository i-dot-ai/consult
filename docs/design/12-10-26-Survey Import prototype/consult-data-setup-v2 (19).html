Why you can trust it

Consult publishes the material most government AI tools keep hidden: the exact prompts it uses, its accuracy against real consultations, and how its work compares with people doing the same task.

Consult analyses files of consultation responses. These five steps upload the file, check it and confirm the question type.

Importance of getting this set up right

Every question is either open, closed or hybrid and that impacts the format in the app

Open questions are free text. Consult reads every answer and groups them into themes, which can then be edited, merged and signed off. Those themes allow for analysis.
Closed questions have a fixed set of answers. Consult enables these answers to act as filters, so you can read the themes for one sector, region or respondent type at a time.

    IDR-006 D Active

    Button, chip and control hierarchy

    • Accent blue now means one thing: an action. It appears on the single primary button per screen, and on links. Nowhere else.
    • The open/closed control was accent-filled, which made a state look like the thing to press — competing with the real Continue button on the same screen. It is now a segmented control: grey track, selected segment lifts to white with a hairline border. Reads as a setting, not a call to action.
    • Pagination had the same fault. The current page is now a quiet neutral fill; the other pages are plain text buttons. A page number is a position, not an action.
    • Selected cards — source picker, filter type — use a strong neutral border and a tick rather than an accent border and blue tint. Selection is never accent.
    • Counts are chips: grey pill, no border, secondary text. Distinct from buttons at a glance because chips have no border and never react to hover.
    • The result: on any screen you can find the one thing to press without reading. That was true in Minute and I broke it by borrowing the colour without the rule.

    IDR-007 D Active

    Four question types, and how hybrid works

    • Open, closed, hybrid and demographic — matching the four kinds the live data template already asks teams to sort their questions into.
    • Hybrid is shown as a type and stored as a link. A type is one value on one question and cannot record which question the pair explains. A link has a direction and a target, so extending from one paired question to several is adding a row rather than changing the shape. The user sees a type; the data keeps the relationship.
    • The closed column carries it. "Do you agree?" is the hybrid question; "Please explain" stays open. Marking both would count one question twice.
    • Choosing Hybrid by hand opens the pairing picker straight away, because the type means nothing without a partner. Removing the last pairing sets the question back to closed.
    • Still proposed, not applied. A wrong type produces a wrong label; a wrong pairing produces a wrong analysis. Accepting sets the type to hybrid; rejecting is remembered, so the suggestion does not return on the next render.
    • The type control is a dropdown, not a segmented control. Four options do not fit on a table row, and would not have fitted on a narrow screen at three. This is also the answer to the control not scaling.

    RECORDED 23 September 2026

    IDR-008 D Active

    Linked question pairs

    • A hybrid question is two columns — a closed question and the open one that explains it. Step 4 detects the pattern and proposes the link rather than applying it.
    • Proposed, not applied — a deliberate exception. Everything else at step 4 arrives already set. A wrong type produces a wrong label; a wrong link produces a wrong analysis, pairing two unrelated questions. That earns an accept-or-reject rather than a silent default.
    • Stored as a list of links on the question, not as a fourth type. A type is a property of one question; a link has a direction and a target. Held as a list so that extending from one linked question to several is adding a row, not changing the shape. The team has said one-to-many is coming.
    • The label states what the link does rather than that it exists: "Linked to Q7 — its answers can be filtered by this one". A bare "Linked to Q7" says nothing about why anyone would want it.
    • The pair is drawn as a pair only in the lock modal, where nothing is sorted or paged. On the table the link sits inline on the closed question, because bracketing two rows breaks when they are sorted apart, paged apart, or stacked on a narrow screen.
    • Every closed question offers "Link to a question" whether or not the pattern was detected, so the control exists even when detection misses.
    • It removes a decision from step 5, as demographic did. A linked question filters its partner by definition, so the filter-type control disappears for it.
    • Detection is a wording rule — "please explain", "why did you", "if so" — on an open question immediately following a closed one. Not a model, and not attributed as one.

    IDR-009 D Active

    Where AI is, and is not

    • Nothing in this flow is a model. Question type detection is a rule — few distinct answers and short ones read as closed, a wording pattern reads as demographic. Duplicate grouping is a case-insensitive comparison. Scale detection is a lookup against three known vocabularies. Validation is structural checks on the file.
    • So nothing here is attributed to AI, deliberately. The flow says "our suggestion" and "changed from our suggestion". Calling a rule an AI suggestion would overclaim, and it would spend the attribution where it is not needed.
    • AI is named only where it is real: theme-finding, which happens after set-up ends. The landing page, the lock modal and the finish screen describe it; nothing in set-up performs it.
    • The previous prototype labelled type detection "AI suggested" — and did not apply the suggestion, so the label announced a decision the product had declined to make. A parallel prototype by another designer attributes AI only to theme-finding, and carries an unused aiSuggested field that is never surfaced. Two of three arrive at the same position.
    • If detection later becomes a model, this needs revisiting. The rule is that attribution belongs once per context at the point of decision — so a model-driven suggestion would earn a mention at step 4, and a rule does not.

    IDR-011 D Active

    Demographic as a third question type

    • Step 4 now offers open, closed or demographic. Previously two types, which put the flow out of step with three other artefacts: the live data template sorts questions into four kinds, the dashboard renders demographics as filter facets, and a parallel prototype by another designer already treats demographic as a question-level type.
    • Demographic is detected from question wording — respondent type, sector, region, responding as an individual or an organisation, and similar — and only where the answers form a small set. Applied as a suggestion, like the other types, so it stays a review.
    • It removes a decision rather than adding one overall. Step 5 previously asked, for every closed question, whether it should filter the dashboard or stand on its own. That question was really asking "is this demographic?". Answered at step 4, demographic questions arrive at step 5 as filters with nothing to choose, and the filter-type control only appears for genuinely closed questions.
    • Step 5 now covers closed and demographic together, since both are counted and both need a dashboard label and their answers grouping. Its heading is "counted questions" rather than "closed questions".
    • The lock modal reports all three counts and says what each produces: themes, charts, filters.
    • Neither the previous prototype nor the parallel one by another designer names the question types in their preparation guidance — both introduce them at the point of decision. Same here, and deliberately: preparation is about the shape of the file. The one exception is keeping demographic columns, which is a preparation action with a real cost if missed.
    • The warning about getting a type wrong has gone from the landing page. It described a consequence before anyone had seen a question, so it asked for concern rather than giving context. Step 4 does the work instead: types arrive suggested, real answers sit beside each question, and the type control is on the row.     IDR-018 D Active

    Consultations page, matched to scope

    • Evaluation, themes and dashboard are links under the name, not columns. A column promises a value that differs by row; these were the same three words on every row, so they carried nothing to scan or sort. Under the name they read as what they are: the ways into that consultation. The table is Name, Date created, Team, Actions.

    • Pagination uses the same pattern as the question table: a range, page numbers, and a page size.
    • Ten rows per page is the default on every table in the product, matching the live product. It applies here and on the question table at step 4, and should apply to any table added later. A user can change it per table; the default does not change.
    • The count under the heading is the size of the list. It carried deletions in progress until IDR-053 removed them.
    • Results appear in a box above the table that can be dismissed, so a confirmation does not sit there indefinitely.
